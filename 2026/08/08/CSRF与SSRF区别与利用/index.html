CSRF 与 SSRF 区别与利用

发表于 2026-08-08 更新于 2026-09-01 分类于 Web 渗透 本文字数： 1.1k 阅读时长 ≈ 4 分钟

0x00 前言

CSRF 和 SSRF 只差一个字母，本质却完全不同。本文对比两者原理、利用面与防御，作为速查。

仅用于合法授权环境的安全研究。

0x01 本质对比

CSRF SSRF
全称 Cross-Site Request Forgery Server-Side Request Forgery
受害者 用户浏览器 应用服务器
关键条件 用户已登录目标站 服务端发起外部请求
利用方向 用户冒充 服务端冒充
攻击面 改密码、转账、删帖 内网穿透、读元数据、攻击内网服务

0x02 CSRF 原理与利用

原理

用户登录站点 A 后访问恶意页面 B，B 中包含对 A 的请求。浏览器自动带 A 的 Cookie，A 把这当成合法请求执行。

用户打开后浏览器尝试加载图片 → 触发转账请求 → 带 Cookie 完成。

CSRF 的限制

  • 必须有有效 Session
  • 不能读取响应（同源策略）
  • 只能做”用户能做的事”

0x05 防御

1. CSRF 防御

  • CSRF Token：表单/接口加不可预测 token，服务端校验
  • SameSite Cookie：SameSite=Strict 或 SameSite=Lax
  • 双重 Cookie：自定义 Header + Cookie 携带同一 token
  • Referer 校验（弱，可绕过）
  • 敏感操作二次验证（验证码、密码）

2. SSRF 防御

  • 白名单域名：只允许请求指定外部域名
  • IP 校验：禁止访问 127/8、10/8、172.16/12、192.168/16、169.254/16、::1
  • 协议白名单：只允许 http/https
  • 解析后直连：一次 DNS 解析，禁用重定向
  • 关闭云元数据端点访问：云厂商建议绑定防火墙
  • 出口网关：业务服务器不出网，只能经代理
  • 禁用危险协议：file、gopher、dict、netdoc

0x06 工具推荐

  • Gopherus：生成 gopher 协议 payload
  • SSRFmap：自动化 SSRF 利用
  • cloudevader：云元数据探测
  • Burp Collaborator / interactsh：盲 SSRF 回连

0x07 总结

CSRF 是”借用户的身份”；SSRF 是”借服务器的位置”。CSRF 看 SameSite + Token，SSRF 看白名单 + 协议过滤。两者放一起记不会忘。
