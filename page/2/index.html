0x03 Follow Stream 分析

右键一个包 → Follow → TCP Stream。把整个会话拼成红/灰两色文本（红=客户端→服务端，灰=服务端→客户端），非常适合：

  • HTTP 完整请求 / 响应
  • SMTP 邮件原文
  • 明文协议回放
  • FTP / Telnet 凭据

输出格式：原始数据、ASCII、Hex Dump、C 数组、JSON。

0x04 统计与可视化

菜单 用途
Statistics → Capture File Properties 概览抓包时长、包数、字节数
Statistics → Protocol Hierarchy 协议占比，发现异常协议
Statistics → Conversations 流量排行（IP/端口）
Statistics → Endpoints 端点流量统计
Statistics → I/O Graphs 流量时间图，看出峰值
Statistics → Flow Graph 时序流程图

0x05 实用快捷键

Ctrl+R 重载当前文件
Shift+Ctrl+B 看包头 16 进制
Ctrl+T 时间参考切换

0x06 抓包模式选择

  • Promiscuous mode：网卡混杂模式，接收同网段所有包。仅限有线网络，无线需 monitor mode。
  • Monitor mode：无线抓 802.11 管理帧、邻居流量。需要支持 monitor 的网卡（如 Atheros AR9271）。

0x07 TLS 解密

服务端私钥解密老式 RSA（不支持 ECDHE 前向保密）。现代 TLS 1.3 必须用 SSLKEYLOGFILE：

Wireshark → Preferences → Protocols → TLS → (Pre)-Master-Secret log file 指定上述文件，重启浏览器即可看到完整 HTTPS 内容。

取证场景对受害机做 SSLKEYLOGFILE 是金标准。

0x08 学习资源

  • Wireshark User’s Guide
  • CloudShark 公开 pcap 库
  • Malware Traffic Analysis 恶意流量练习

0x09 总结

过滤器是 Wireshark 的灵魂，30 行常用过滤就够 90% 场景。配合 Follow Stream 和 Statistics，几乎能拼出任意协议的故事。

0x04 代码层防御要点

1. 白名单（不是黑名单）

2. 重命名

0x00 前言

XSS（跨站脚本）是 Web 安全三大经典漏洞之一，长期占 OWASP Top10 榜首区域。本文梳理三类 XSS 的本质差异、利用方式与防御要点。

仅用于合法授权环境的安全研究。

0x01 三种类型对比

类型 持久化 触发条件 危害
反射型 否 用户点击恶意链接 中（依赖诱导）
存储型 是 用户访问被注入的页面 高（自动触发）
DOM 型 否 前端 JS 渲染污染 中

原理

0x04 DOM 型 XSS

原理

不经过服务端，前端 JS 直接操作 DOM 时使用未过滤的输入。

访问 https://target.com/#<img src=x onerror=alert(1)> 即可触发，服务端日志看不到。

容易出问题的 sink

0x05 危害与利用

XSS 能做的远不止弹窗：

  1. 窃取 Cookie / Session：document.cookie
  2. 键盘记录：监听 keydown 事件
  3. 强制请求：伪造用户行为，例如改密码
  4. 内网探测：扫描内网端口、服务
  5. 持久化：注入 JS 后台自动修改资料维持访问
  6. BeEF 框架集成：把目标 hook 到 BeEF，可远程控制浏览器

0x06 XSS 平台/框架

  • BeEF：浏览器利用框架，可下发命令、模块化攻击
  • XSStrike：自动化 XSS 检测工具，含上下文分析
  • XSSer：批量测试工具
  • XSS-Challenge：练习靶场

0x07 防御

1. 输出编码（最关键）

按输出位置选择编码：

  • HTML 上下文：HTML 实体编码（< → &lt;）
  • 属性上下文：属性编码（双引号 → &quot;）
  • JS 上下文：JSON.stringify 或 \xXX 编码
  • URL 上下文：URL 编码

2. CSP 内容安全策略

  • 禁用内联脚本（需配 nonce 或 hash）
  • 白名单加载源

3. HttpOnly Cookie

XSS 也拿不到 cookie。

4. 输入校验（辅助）

  • 长度限制
  • 黑/白名单关键字符
  • 字段类型强校验（如纯数字 ID）

0x08 练习靶场

  • xsses.forEach
  • DVWA 各等级 XSS 模块
  • XSS Challenge by Google
  • PortSwigger XSS Labs

0x09 总结

XSS 不复杂，但工程化防御难。输出编码 + CSP + HttpOnly 三板斧走天下，永远不要 innerHTML 不可信数据。

BurpSuite Intruder 入门笔记

发表于 2026-06-10 更新于 2026-09-01 分类于 工具使用 本文字数： 677 阅读时长 ≈ 2 分钟

0x00 前言

BurpSuite 是 Web 渗透最常用的工具没有之一。Intruder 模块负责自动化批量请求，是爆破、fuzz、批量注入的核心。本文梳理 Intruder 的 4 种攻击模式、Payload 类型与实战技巧。

仅用于合法授权的安全研究。

0x01 四种攻击模式

模式 适用场景 请求数
Sniper（狙击手） 单一变量爆破（如密码字段） Payload 数
Battering Ram（攻城槌） 多变量同时用同一 Payload Payload 数
Pitchfork（草叉） 多变量并行（一一对应） 最小 Payload 数
Cluster Bomb（集束炸弹） 多变量笛卡尔积（最常见） 各 Payload 数之积

举例：登录爆破，用户名 admin，密码字段是变量 → 用 Sniper；用户名和密码都爆破 → 用 Cluster Bomb。

0x02 实战：登录爆破

1. 抓包发送到 Intruder

Proxy → Intercept 抓到登录请求 → 右键 Send to Intruder。

2. 设置变量

进入 Intruder → Positions，点击 Clear § 后手动选中密码字段的值，点击 Add §：

3. 加载字典

Payloads 标签：

  • Payload type: Runtime file
  • 加载 SecLists 中的密码字典：/usr/share/seclists/Passwords/Common-Credentials/10-million-password-list-top-10000.txt
  • 关闭 URL 编码（密码含特殊字符时按需）

4. Grep 提取结果

Options → Grep - Extract → 添加匹配字符串：

  • 失败：incorrect / password_error / HTTP 401
  • 成功：logout / welcome / HTTP 302 跳转

5. 开始攻击

Start attack，根据 Length 或 Status 列定位异常响应 → 成功爆破。

0x03 高频技巧

1. 并发限速

避免触发 WAF/封 IP：

  • Resource Pool → Maximum concurrent requests = 5
  • Delay between requests = 200ms

2. Payload 处理

  • Match/Replace：替换 § 中内容前做大小写变换
  • Payload Processing → Add → Skip if matches → 过滤已知失败结果
  • Character mapping：避免特殊字符被 URL 编码

3. 多阶段爆破

如登录后还要绕 2FA：

  1. 第一个 Intruder：登录 → 拿到 Session
  2. 宏（Macro）→ 自动用上一步 Session 发起下一个请求
  3. 第二个 Intruder：爆破 2FA

0x04 Payload 类型清单

类型 用途
Simple list 简单词表
Runtime file 加载外部字典文件
Custom iterator 字符组合生成器（如 4 位数字）
Numbers 数字序列（如 ID 枚举）
Dates 日期生成
Username generator 用户名自动生成
Random string 随机字符串 fuzz
Bit flipper 二进制位翻转（适合 fuzz 二进制协议）
Case modification 大小写变换

0x05 防御侧

  • 限制单 IP 单账号每分钟登录次数 ≤ 5
  • 失败 N 次后启用图形验证码
  • 密码复杂度策略（长度 ≥ 12，含大小写数字符号）
  • 异地登录二次验证
  • 监控同 IP 多账号尝试

0x06 总结

Intruder 不难，难在字典质量与 Grep-Match 的精准度。一份 SecLists + 一个清楚的差异点 = 高效爆破。
