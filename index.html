SQL 注入从入门到实战笔记

发表于 2026-08-28 更新于 2026-09-01 分类于 Web 渗透 本文字数： 584 阅读时长 ≈ 2 分钟

0x00 前言

SQL 注入长期占据 OWASP Top10 头部位置，是 Web 渗透中最经典、杀伤力最强的漏洞之一。本文梳理基础原理、常见类型与实战 Payload，作为学习笔记存档。

注：本文仅用于合法授权环境下的安全研究。

0x01 原理

后端直接将用户输入拼接到 SQL 语句中，未做过滤或参数化，导致攻击者可以改变 SQL 语义。

典型漏洞代码（PHP）：

输入 id=1 OR 1=1 后，SQL 变成 SELECT * FROM users WHERE id = 1 OR 1=1，返回全部用户。

0x02 分类

按注入点位置分：

类型 特征 示例
回显注入 结果直接返回页面 union select
报错注入 利用数据库报错带出数据 extractvalue, updatexml
盲注 无回显，靠布尔/时间判断 and sleep(5)
二次注入 数据先存入再触发 注册处存 payload

0x03 实战 Payload 集

1. 联合查询注入 (Union-based)

2. 报错注入 (Error-based)

3. 布尔盲注

4. 时间盲注

0x04 防御

  1. 参数化查询（最佳方案）：使用 PDO 预编译 / MyBatis #{} / Java PreparedStatement。
  2. 输入校验：白名单校验类型、长度。
  3. 最小权限：DB 账号只读 + 只能查指定库。
  4. WAF：作为补充防线，不能替代代码层防御。
  5. 审计：对自研 ORM 重点 review。

0x05 工具推荐

  • sqlmap：自动化注入神器，支持 6 大数据库
  • BurpSuite Intruder：手工测试 + 批量 fuzz
  • NoSQLi Scanner：NoSQL 注入场景

0x06 结语

SQL 注入虽”老”，但每年仍有大量在野漏洞。理解原理 + 多看 Payload + 多打靶场（sqli-labs、DVWA），是掌握它的唯一路径。

CSRF 与 SSRF 区别与利用

发表于 2026-08-08 更新于 2026-09-01 分类于 Web 渗透 本文字数： 1.1k 阅读时长 ≈ 4 分钟

0x00 前言

CSRF 和 SSRF 只差一个字母，本质却完全不同。本文对比两者原理、利用面与防御，作为速查。

仅用于合法授权环境的安全研究。

0x01 本质对比

CSRF SSRF
全称 Cross-Site Request Forgery Server-Side Request Forgery
受害者 用户浏览器 应用服务器
关键条件 用户已登录目标站 服务端发起外部请求
利用方向 用户冒充 服务端冒充
攻击面 改密码、转账、删帖 内网穿透、读元数据、攻击内网服务

0x02 CSRF 原理与利用

原理

用户登录站点 A 后访问恶意页面 B，B 中包含对 A 的请求。浏览器自动带 A 的 Cookie，A 把这当成合法请求执行。

用户打开后浏览器尝试加载图片 → 触发转账请求 → 带 Cookie 完成。

利用 3：JSON 接口 CSRF

巧用 enctype 绕过 Content-Type 检查。

CSRF 的限制

  • 必须有有效 Session
  • 不能读取响应（同源策略）
  • 只能做”用户能做的事”

原理

0x05 防御

1. CSRF 防御

  • CSRF Token：表单/接口加不可预测 token，服务端校验
  • SameSite Cookie：SameSite=Strict 或 SameSite=Lax
  • 双重 Cookie：自定义 Header + Cookie 携带同一 token
  • Referer 校验（弱，可绕过）
  • 敏感操作二次验证（验证码、密码）

2. SSRF 防御

  • 白名单域名：只允许请求指定外部域名
  • IP 校验：禁止访问 127/8、10/8、172.16/12、192.168/16、169.254/16、::1
  • 协议白名单：只允许 http/https
  • 解析后直连：一次 DNS 解析，禁用重定向
  • 关闭云元数据端点访问：云厂商建议绑定防火墙
  • 出口网关：业务服务器不出网，只能经代理
  • 禁用危险协议：file、gopher、dict、netdoc

0x06 工具推荐

  • Gopherus：生成 gopher 协议 payload
  • SSRFmap：自动化 SSRF 利用
  • cloudevader：云元数据探测
  • Burp Collaborator / interactsh：盲 SSRF 回连

0x07 总结

CSRF 是”借用户的身份”；SSRF 是”借服务器的位置”。CSRF 看 SameSite + Token，SSRF 看白名单 + 协议过滤。两者放一起记不会忘。
